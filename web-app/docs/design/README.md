## Предлагаемое решение

Модульный монолит: Python/FastAPI, PostgreSQL, React/TypeScript, отдельный фоновый процесс из того же backend-проекта. Один API обслуживает основной веб-интерфейс и адаптивный режим сотрудника точки. Локальный запуск планируется через Docker Compose.

Подтверждённые ограничения: шесть недель, 4–6 начинающих участников; заказчик не предоставляет данные, тестовую базу и разработчика 1С. MVP автономный и демонстрационный. Кладовщик составляет внутреннюю накладную, точка подтверждает фактическую приёмку, приложение ведёт свой оперативный журнал. Данные заказчика и качество реальных прогнозов этим не подтверждаются.

1С остаётся источником официального учёта заказчика, который он ведёт самостоятельно. Будущая интеграция только читает 1С; после её появления приложение сможет хранить сверяемую аналитическую копию. Ни приложение, ни LLM не пишут напрямую в таблицы 1С. Самостоятельный журнал приложения и режим сверки со снимками 1С — разные явно выбранные режимы, их нельзя незаметно смешивать.

Самое важное условие будущей сверки: для наложения оперативных операций на остаток 1С необходимо доказуемо знать, какие операции уже включены в снимок. Время снимка или получения продажи само по себе этого не доказывает. Если адаптер не даёт такой гарантии, показываем последний подтверждённый остаток и отдельную оценку расхода; не выдаём их разность за достоверный оперативный остаток.

## Границы достоверности

- Все числа в примерах — синтетические иллюстрации расчёта, а не данные сети.
- Имена API и таблиц ниже — проектируемые контракты нашей системы, а не описание существующей конфигурации 1С.
- Метрики качества прогнозов и бизнес-эффект пока не измерены. Процент точности, снижение списаний и рост продаж не заявляются.
- Будущий учебный стенд обязан показывать «Демонстрационный режим · синтетические данные» в интерфейсе, выгрузках и отчётах экспериментов.
- Неизвестные сведения и временные решения собраны отдельно в документе 00. Ответы заказчика должны обновить решения до подключения реальных данных.

## Первые решения для согласования

Рабочая граница принята из ответов команды: автономный демонстрационный MVP за шесть недель, онлайн, вход по логину и паролю, размещение на выделенном ПК. Следующий шаг — этап 1: словарь данных, минимальные схемы и каркас стенда. Реальное подключение 1С и пилот зависят от будущего решения заказчика предоставить доступ; они не входят в обещанный шестинедельный результат. Разработка всего приложения в текущую задачу не входит.
