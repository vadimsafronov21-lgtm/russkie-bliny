# Состояние реализации · 16 октября 2026

Первый рабочий срез автономного учебного приложения. Основа: [проектирование](../../russkie-bliny-design/README.md). Не весь шестинедельный backlog реализован.

## Реализовано

Каркас FastAPI/React/TypeScript; SQLAlchemy и три Alembic-миграции; PostgreSQL-конфигурация и локальный SQLite; demo-seed; четыре роли, пять пользователей, ограничения объектов на сервере; HttpOnly-сессии, CSRF и ограничение попыток входа; собственный ledger; историческая рецептура; отмена/возврат через API; атомарные резервы склада; заявки и внутренние накладные; отправка; несколько приёмок одной отправки; оптимистическая версия документа и повтор команд; журнал действий; outbox/worker/email sink; русская адаптивная UI; простая аналитика; baseline 1/7/14 и последовательные временные проверки; черновая корзина; локальный backup и проверка восстановления.

История seed не проигрывается повторно поверх начального остатка: эти продажи предшествуют демонстрационной инвентаризации. Повтор seed сохраняет рабочие изменения; он может восстановить времена известности только исходных synthetic-fixtures. Начальная история не дополняется выдуманными продажами автоматически при смене даты. Дни без записей показываются как отсутствие данных.

## Ограничения

- Реальной 1С и исполняемого demo-контракта сверки снимков пока нет. Поле последней синхронизации пустое. Контракт спроектирован в [проектной документации](design/02-integration-contract.md), его тесты нельзя считать пройденными текущими тестами ledger.
- Один учебный склад и фиксированное назначение точек. Одна отправка на заявку; можно принять её несколькими порциями. Отмена после отправки, возврат на склад и закрытие недопоставленного остатка пока не реализованы.
- Нет учёта партий, FEFO, сроков годности, вместимости и реальных графиков поставок. Рекомендация — черновая арифметика с предупреждением, не безопасный автоматический заказ.
- Нет редактирования техкарт/единиц/ролей/политик через интерфейс. Администратор видит технический статус; API списка пользователей доступно только ему. Правила внимания пока фиксированы. Добавки и замены — будущий этап.
- Прогноз — только baseline. CatBoost, GRU, модельный реестр и полноценный воспроизводимый CLI экспериментов не реализованы. Интервал первого дня эмпирический; покрытие не оценивалось, для 7/14 дней интервал отсутствует.
- Погода, новости и LLM не подключены; платных запросов нет. Сменяемые реальные адаптеры, schema extraction, budget ledger и ablation ещё предстоят.
- Email по умолчанию сохраняется в `.eml`, получатель всегда демонстрационный `.invalid`; реальная адресная доставка не подтверждена. Внешняя доставка не имеет гарантии exactly-once.
- RPO/RTO не согласованы, ежедневное расписание backup не настроено. PostgreSQL/Compose/удалённый CI пока не запускались на этой машине.
- Логин по паролю предназначен для локального demo, известные seed-пароли не подходят для сетевой эксплуатации. Нет управления аккаунтами, отзывом сессий администратором и production-инфраструктуры.

## Дальнейшие задачи по приоритету

1. Прогнать миграции и конкурентные тесты на PostgreSQL и проверить Docker Compose на ПК команды.
2. Разделить `main.py` и `App.tsx` по модулям без изменения поведения; выделить документацию API и DTO.
3. Закрытие расхождений, остатка поставки и возврат на склад; история причин и ограничения переходов.
4. Явный журнал доступности меню, настраиваемые правила аналитики/логистики, базовый редактор справочников.
5. Изолированный demo-адаптер 1С: inbox, версии, снимки/coverage, ошибки и тесты двойного списания.
6. Исследовательский запуск baseline/CatBoost/GRU и погодных/событийных признаков на синтетике; не объявлять это подтверждением качества для заказчика.

Срок и объём следующих работ определяются учебным планом. Эта версия демонстрирует процесс, но не подтверждает готовность к реальному учёту сети.
