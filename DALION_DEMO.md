# Демо обмена с ДАЛИОН

Версия от 26.10.2026. Исходники: `russkie-bliny-github`.

Это работающий демонстрационный модуль получения данных, а не готовая интеграция с реальной 1С. HTTP-маршрут, русские имена полей и структура JSON придуманы для этого примера. Они не описывают API ДАЛИОН. Все продажи, цены, рецептуры, пригодность и графики синтетические.

## Запуск

Двойной щелчок по `start_dalion_demo.cmd` или из папки исходников:

```powershell
.\.venv\Scripts\python.exe dalion_demo.py
```

Также в приложении: «Остатки → Данные остатков» или «Спрос → Данные продаж», кнопка **«Демо обмена с ДАЛИОН»** справа.

1. Нажмите «Получить демо-данные». Локальный HTTP-имитатор вернёт полный снимок восьми наборов.
2. Проверьте количество строк, пример последних продаж и сопоставление полей.
3. Нажмите «Открыть демо для анализа». Откроется обычный интерфейс КРОНА на отдельной базе: прогноз, остатки и заявка.
4. Проверьте «Имитировать отсутствие связи» и повторите получение. Ошибка не изменит данные. Снимите флаг для повторной попытки.

С 26.10.2026 вверху доступны четыре демонстрационные ситуации; смена ситуации выделяет новую базу. После открытия анализа можно «Имитировать обновление» и повторно открыть данные через сравнение изменений и конфликтов. Все шесть новых функций и отдельный запуск полной демонстрации описаны в `OPERATOR_FEATURES.md`.

Новая папка создаётся для каждого сеанса под `%LOCALAPPDATA%\RusskieBliny-DalionDemo\dalion-demo-*`. В окне показан точный путь. База и исходный снимок остаются для повторной проверки; автоматически папки не удаляются. Повторно открыть сохранённую базу можно командой `app.py --data-dir <папка-сеанса>`. Рабочая `%LOCALAPPDATA%\RusskieBliny\data.sqlite3` не используется. Повторное открытие анализа в одном сеансе сохраняет ручные правки и историю. Закрытие окна обмена закрывает связанное окно анализа.

## Что реализовано

- `dalion_exchange.py`: локальный GET-сервис на `127.0.0.1` со случайным портом; адаптер `DalionDemoAdapter`; явное сопоставление полей; изолированная демо-база.
- `dalion_demo.py`: получение в фоновом потоке, предварительный просмотр, имитация сбоя связи и открытие анализа.
- Проверка полного снимка, маркировки DEMO, формата JSON, обязательных полей, ссылок, единиц и закрытых дней до записи. Пустые значения и отсутствующие продажи не превращаются в нули. Неизвестная дата партии остаётся пустой.
- Ограничение ответа 4 МБ, тайм-аут 3 секунды, запрет внешних адресов, перенаправлений и системного прокси. Имитационный сервер предоставляет только чтение.
- Загрузка через существующий XLSX-импорт с маркировкой DEMO, транзакцией и защитой от повторного файла. Снимок сервера стабилен в течение сеанса. JSON-оригинал и XLSX сохраняются рядом с демо-базой.

## Граница реальной интеграции

Для подключения к сети нужны точные версия/конфигурация ДАЛИОН, образцы выгрузок или описание доступного сервиса, права на чтение и правила сопоставления точек, блюд, ингредиентов и единиц. Поля пригодности, наличия товара, целевого запаса и графика могут отсутствовать в учётной базе — их нельзя автоматически выдумывать.

Реальный адаптер должен быть отдельным от демонстрационного. Нужно согласовать полноту снимков/изменений, актуальность данных и обработку конфликтов с ручными правками. Текущий общий импорт заменяет таблицы целиком. Демо не реализует запись в 1С, авторизацию терминала, непрерывную синхронизацию или отправку заявки поставщику.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe dalion_demo.py --demo-root qa/dalion-demo-data --smoke qa/dalion-demo-smoke
```

Вторая команда проверяет получение, импорт, открытие интерфейса и расчёт; сохраняет `exchange.png`, `analysis.png` и `result.json`. Она создаёт только новую демо-папку.
