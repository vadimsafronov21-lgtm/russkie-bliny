При обычном запуске используется `%LOCALAPPDATA%\RusskieBliny\data.sqlite3`. Перемещение EXE не переносит базу. Первый запуск без существующей базы создаёт явно помеченные синтетические данные; последующие запуски сохраняют изменения. Резервное копирование доступно в настройках.

## Воспроизведение сборки

На Windows с Python 3.13 из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe build.py
```

`build.py` создаёт один оконный EXE через PyInstaller и включает `assets`. `requirements-build.txt` фиксирует использованные версии инструментов. Повторная сборка может иметь другую бинарную контрольную сумму; хеши исходников и выданного файла зафиксированы в [release-manifest.json](release-manifest.json).

## Проверка выпуска

Результаты текущего прогона находятся в [qa/release-2026-10-28](qa/release-2026-10-28). Расширенный `--smoke` проверяет основные операции, экспорт Excel и 14 групп действий новых модулей. В отчёте собранного EXE поле `frozen` должно быть `true`.

Для повторной проверки нужно обязательно указать новую отдельную папку данных, например:

```powershell
.\dist\RusskieBliny.exe --data-dir C:\Temp\Bliny-check-UNIQUE --smoke C:\Temp\Bliny-results-UNIQUE
```

Папки должны быть новыми: проверка изменяет синтетические остатки, создаёт заявки и демонстрационные сценарии. Рабочая база пользователя при проверке выпуска не использовалась.

Модуль ДАЛИОН проверяется на локальном HTTP-имитаторе и четырёх независимых синтетических наборах. Подключение к реальной 1С, вход через терминал и отправка поставщику этим выпуском не подтверждаются.
