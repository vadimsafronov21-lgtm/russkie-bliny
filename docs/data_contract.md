# Контракт данных

Все CSV в UTF-8 (BOM допустим), разделитель запятая, десятичная точка, даты `YYYY-MM-DD`, первая строка — заголовки. Идентификаторы — непустые строки, стабильные во всех файлах. Названия колонок остаются английскими для удобства Python; интерфейс показывает русские заголовки. Пустые `stock`/`deliveries`/`sales` допустимы **с заголовками**. Справочники, рецептуры, параметры закупки и календарь пустыми быть не могут.

| Файл / таблица | Колонки | Ключ |
|---|---|---|
| sales | date, store_id, dish_id, quantity | дата + точка + блюдо |
| dishes | dish_id, name, introduced_on | dish_id |
| ingredients | ingredient_id, name, base_unit | ingredient_id |
| recipes | dish_id, ingredient_id, quantity, unit | блюдо + ингредиент |
| stock | lot_id, store_id, ingredient_id, quantity, unit, expires_on | lot_id |
| deliveries | delivery_id, ingredient_id, store_id, quantity, unit, arrival_date, expires_on | delivery_id |
| purchase_params | store_id, ingredient_id, lead_days, review_days, pack_size, min_order, unit, shelf_life_days | точка + ингредиент |
| calendar | date, store_id, is_open | дата + точка |

`sales.quantity` — порции; `recipes.quantity` — расход на одну порцию; `stock.quantity` — пригодное/непригодное количество в конкретной партии по состоянию на конец as_of; `deliveries.quantity` — ожидаемая партия. `is_open` равно 0 или 1. `introduced_on` — день ввода блюда: продаж раньше быть не должно. В первой версии все блюда справочника считаются доступными всем точкам после introduced_on.

`lead_days` — целое число календарных дней от размещения заказа до поступления (0 допустим). `review_days` — положительное число дней между пересмотрами. `shelf_life_days` — положительная годность новой заказанной партии с дня поступления включительно. `pack_size > 0`, `min_order >= 0`, обе величины в unit. Параметры должны существовать для каждой точки и каждого используемого ингредиента.

Базовые единицы ingredients: `kg`, `l`, `pcs`. В остальных таблицах колонка unit обязательна. Импорт явно применяет: `g → kg × 0.001`, `ml → l × 0.001`, остальные ×1. Массу в объём не переводим; неизвестные единицы и несовместимые размерности — ошибки. Например `I01,45,g` в рецептуре муки станет `0.045 kg`. Количество яйца в рецептуре может быть дробным (доля яйца на порцию); закупка округляется до упаковки.

**Ноль и отсутствие записи:** открытый день без продаж блюда должен содержать запись quantity=0, если нулевые продажи подтверждены. Отсутствие записи даёт предупреждение и неизвестное наблюдение, оно не заполняется нулём и не участвует в среднем/метриках. Закрытый день в календаре получает нулевой прогноз, однако его исторические нули исключены из обучения среднего. Пропущенный день календаря — ошибка. Календарь должен покрывать все дни от начала истории до as_of и все дни планирования включительно.

Проверяются пустые поля, нечисловые/бесконечные/отрицательные значения, повтор ключей, даты, ссылки, календарь, целые интервалы поставок и совместимость единиц. Дубли продаж не суммируются молча: агрегируйте события кассы до строки за день/блюдо/точку. Повторы разных ингредиентов внутри рецепта также агрегируйте самостоятельно. Ошибка содержит файл/поле и действие для исправления.

Срок expires_on включителен: партию можно израсходовать в этот день; со следующего дня она недоступна. Товар с expires_on <= as_of не покрывает первый день плана. Поставка должна поступать **после as_of**; уже поступившее переносится в stock. expires_on не может быть раньше arrival_date. Расход и приход происходят в начале/в течение календарного дня, внутридневного порядка нет.

SQLite создаёт те же восемь таблиц, дополнительную `stores` из календаря и `metadata` для даты снимка. Схема находится в `repository.DDL`, внешние ключи включены. Импорт выполняется после полной проверки одной транзакцией. База хранит текущий снимок, а не журнал движения и версий.
