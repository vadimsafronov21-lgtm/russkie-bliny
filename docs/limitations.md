# Допущения и ограничения первой версии

- Продажи — приближение спроса. Информации о стоп-листе, потерянных продажах и отсутствии блюд нет; такое ограничение показывается при каждом расчёте. Нет попытки «восстановить» неизвестный спрос без данных.
- Все комплектные данные учебные и синтетические. Точность на них не подтверждает точность на предприятии.
- Прогноз объяснимый: только два простых метода и резервное среднее. Не учитываются цены, акции, праздники, погода и тренды; нет интервалов неопределённости. Для нового блюда без продаж требуется отдельно согласованный экспертный прогноз; встроенной формы ввода такого прогноза пока нет.
- Пропущенные продажи исключаются, нули сохраняются. Пропуски могут быть неслучайными и смещать средние. MAE/WAPE выбора не являются независимой итоговой оценкой качества.
- Склад — снимок на конец as_of. Не моделируются отгрузки/возвраты, незавершённое производство, отходы готовки, технологические потери и взаимозаменяемость ингредиентов. Изменения рецептур во времени не поддерживаются.
- Количество ингредиента — кг/л/шт. Для перевода массы в объём нужна плотность; она не угадывается. Потребность в долях яйца допустима, физическая закупка округляется до упаковки.
- Даты поставок и сроки годности известны. Дни календарные, доставка утром, годность включительна. Нет случайных задержек; сценарий задержки меняет ожидаемую дату явно. Заказы можно размещать каждый календарный день; календарь поставщика/праздники надо уточнить.
- FEFO применяется независимо для каждого ингредиента. Дефицит разных ингредиентов не снижает прогноз выпуска блюда и расход остальных ингредиентов: такой прототип может завысить их потребность при остановке кухни.
- Страховой запас — упрощённый процент потребности L+R, а не статистически гарантированный уровень обслуживания. Параметр 15% выбран для демонстрации.
- Заказ — одна партия, сроки/упаковка/минимум учитываются, но стоимость, вместимость склада, бюджет и многопартийная оптимизация отсутствуют. Если годность короче периода, программа предупреждает об остаточном дефиците/буфере и списаниях; окончательный график поставок согласует человек.
- Остаток после окончания периода с будущим сроком годности имеет только оценку риска списаний: последующий спрос не проверен. Отдельно показывается фактически неиспользованная до срока партия внутри периода.
- Все блюда справочника введены одновременно для всех точек согласно introduced_on; ассортимент конкретной точки и даты вывода блюда потребуют дополнительной таблицы. Демонстрация включает одну точку.
- SQLite хранит текущий набор, не версии импортов. Нет пользователей, сетевого режима, разграничения прав, журнала изменений и автоматической отправки заказа. Импортировать следует доверенные подготовленные CSV; резервное копирование — обычная копия файла базы после закрытия приложения.
- Интерфейс показывает первые 500 строк исходной таблицы для скорости, а расчёт использует все строки. Общий отчёт экспортируется полностью. Конфигурация редактируется в JSON, встроенного редактора параметров нет.

Прототип рассчитан на обучение и демонстрацию. Для практического применения нужно согласовать данные, проверить прогноз на реальной истории и проверить закупки с технологом/менеджером точки.
